# 第三方用户视角审查 · 1.6.2

日期：2026-09-04。审查对象：连续影像 / FrameCurrent 的首次启动、创作/观看流程、异常恢复与 GitHub 包装。

## 结论

产品的 AI 电视台概念与品牌视觉已经成立，但原版对新用户的启动引导不足，部分状态容易让人误以为已连接模型或正在实时播放。此次优先改善“能启动、能看懂、付费有边界、失败能取回作品”，不扩大为公共 SaaS 或长剧情生成系统。

| 原问题 | 已完成的优化 |
|---|---|
| 环境检查只认工具路径，可能扣费后才发现无法处理视频 | 实际编译、运行探测及目录写入检查；首个收费请求前再次预检 |
| 网站关闭后不知道如何恢复，重复启动报端口错误 | 启动器复用同版本同目录实例；冲突时明确提示，绝不自动杀进程 |
| 本机健康被显示成“AI服务在线” | 区分本机连接与 fal 账户验证；断线提示及重新连接 |
| 默认5分钟，容易把成片长度误认为等待时长 | 默认30秒试片，标明生成需等待；保留自由时长与不限时模式 |
| 灰色开播按钮没有原因 | 根据实际状态解释当前缺少的条件，提供 Key 获取入口 |
| 换台隐藏了仍在收费生成的任务 | 全局活动频道提示、返回入口、刷新找回、阻止冲突开播 |
| 丢失开播响应后可能卡旧作品或沿用旧请求编号 | 自动载入新任务，并通过只读精确查询核对旧请求编号后核销 |
| 中途停止显示已保存，但没有直接取回入口 | 提供每幕下载；不伪装成已经合成完整片 |
| 退出时取消可能遗漏、HEAD未沿用保护路由 | 关闭门禁、原子取消与有限收尾；HEAD与GET使用同一访问边界 |
| 小字说明难读，隐藏单选控件的焦点不可见 | 放大关键说明、增强键盘焦点和减少动态效果支持 |
| README更像内部验收记录，缺少完整安装/排错路径 | 面向用户重排、中文使用指南、英文介绍、真实CI状态入口 |

保留：五个预设、独立自定义频道、仅自定义显示节目设置、横/竖屏、现有 Logo/频道美术、Apache-2.0 与品牌商标保留。没有新增常驻预算大面板。

- 原有71项Python测试继续通过，新增测试覆盖本次启动、安全与恢复修改。
- 不含历史作品和编译缓存的源码副本完成首次媒体编译并成功启动。
- 当前本机首页与健康接口返回HTTP 200；正常启动终端保持运行。
- 本次没有发送收费生成，也没有把历史片段当成本版本新的5分钟验收证据。
- 前端测试使用DOM替身；字体、换行、200%缩放、键盘完整操作与真实播放仍需浏览器人工验收。不能把离线通过称为视觉验收完成。
